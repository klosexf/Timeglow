# 开发与计时说明

产品介绍与界面展示见 [README](../README.md)。本文说明原生工程的运行、计时与验证方式。

## 项目结构

| 路径 | 内容 |
| --- | --- |
| `Timeglow/` | SwiftUI / AppKit 界面、贴边书签、主窗口与自我提醒窗口 |
| `Timeglow/Monitoring/` | 应用采集、浏览器读取、系统权限与监控控制 |
| `Timeglow/MonitoringCore/` | 区间模型、计时、统计、提醒规则与 SQLite 存储 |
| `Tests/` | 核心逻辑测试与网站图标检查 |
| `Branding/` | 产品图标源文件与生成说明 |
| `docs/images/` | README 使用的界面截图与效果图 |

## 构建与运行

用 Xcode 26 或更新版本打开 `Timeglow.xcodeproj`，选择 Timeglow / My Mac，配置可用的开发签名证书后运行。应用工程最低系统版本为 macOS 26.0；`Package.swift` 中核心库的 macOS 14 声明不代表整个应用兼容 macOS 14。

也可在仓库根目录执行：

```sh
bash scripts/build-development.sh
open ../outputs/native/Timeglow.app
```

脚本默认构建 Debug / arm64，使用 `/Applications/Xcode.app/Contents/Developer`；可通过 `DEVELOPER_DIR` 指定其他 Xcode。工程保留 App Sandbox 与 Hardened Runtime，开发包尚未公证，也未提交 Mac App Store。

常用开发包固定为仓库同级的 `outputs/native/Timeglow.app`。构建脚本会取消同一 bundle ID 的历史评审包启动注册，再注册这个开发包，保留历史文件和用户数据。更新时先正常退出旧进程，再构建并用完整路径启动。排查旧界面或通知路由时，核对进程路径、加载的 Debug 模块与构建指纹。

## 启动与窗口行为

- 运行后开始自动计时，只显示贴边书签与菜单栏图标，不自动打开统计或设置。
- 应用不在 Dock 与应用切换器中显示图标；再次打开正在运行的应用也不会自动打开主窗口。
- 点击书签展开概览，通过「查看统计」或齿轮进入主窗口；`⌘,` 和菜单栏「设置…」打开设置。
- 关闭主窗口后继续记录；「退出 Timeglow」结束当前区间并保存。
- 点击系统通知打开独立的自我提醒窗口；关闭提醒不暂停计时。
- 设置按「用时与提醒」「统计范围」「权限与计时」「启动与数据」分组。提醒节点与文案需要保存，其余分类即时保存；切换分类保留提醒草稿。

## 计时口径

应用、网站和 `active` / `idle` / `suspended` 区间独立保存，统计时取交集。所选应用和网站的使用时长合并计算，与每日限额比较并用于提醒。取消选中的项目仍正常记录用时，但不加入这份合计。

网站属于浏览器的明细。选中整个浏览器后，其中所有网站都会计入合计，即使未单独选中网站；同一段用时只计算一次。域名规则包含子域名，路径与参数不参与匹配。已由启用的父域名规则覆盖的网站显示为已添加，重新启用已关闭的网站不会产生重复规则。

统计页可直接将应用或网站加入范围。范围变化后当前周期的合计立即重算，暂停记录时也会刷新。

闲置达到阈值后，回溯扣除等待区间。提醒依据已确认的输入活动计算，避免等待期结束后留下误报。观看长视频或阅读时，可延长闲置阈值或关闭自动闲置排除。

每 5 秒保存稳定 UUID 的区间检查点，同一区间更新，不按心跳重复插入。退出、休眠、暂停后不继续延长区间，重启不补算应用未运行的空档。每日限额保存快照；历史状态颜色按当前状态分界显示。

汇总和界面用时约每 5 秒更新，应用切换等边界可立即更新。区间按实际事件时间戳计算，不将时长取整为 5 秒。提醒在汇总时检查节点，可能延后一个刷新周期。

## 数据存储与性能

相对于应用自己的 Application Support 目录：

| 构建 | 数据库位置 |
| --- | --- |
| Debug | `Timeglow/Development/usage.sqlite` |
| Release | `Timeglow/usage.sqlite` |

App Sandbox 下，Application Support 位于应用容器内。两种构建不混用计时记录和提醒设置。可从「启动与数据 → 查看位置」定位当前数据库。

今日缓存按 UUID 增量替换，不在每次保存后重新读入全天明细。历史报表由后台任务和独立只读数据库连接生成，按天分组，今日趋势按小时分组；不为每一天重复扫描全历史。关闭主窗口或收起概览后释放对应视图和统计任务，再次打开时重新读取。

暂停、锁屏、屏幕睡眠及会话离开时停止采样定时器。闲置时保留每秒一次的轻量输入状态检查以检测恢复，停止重复汇总、网站读取和定期保存。午夜通过系统日期通知更新「今天」，无需在暂停时持续轮询。

## 权限与网站图标

- 应用身份通过 `NSWorkspace` 获取，无需辅助功能或录屏授权。
- 闲置检测只使用系统距上次输入的时间，不读取键入内容。
- 网站读取仅支持 Safari、Google Chrome。用户主动点击时申请自动化授权；轮询不重复请求权限，也不启动已退出的浏览器。
- 浏览器自动化使用沙盒 Apple Events 目标例外，仅声明 Safari 和 Chrome；这不代表 Mac App Store 审核批准。
- 系统通知与登录项均由用户点击后申请或开启。
- CSV 导出使用系统保存面板，仅声明用户选定文件的读写能力。

展开浏览器明细时按需获取网站图标：先读取对应网站的 HTTPS favicon，缺失时从公开首页查找声明的图标。请求不使用浏览器 Cookie 或登录凭据，不接入第三方图标查询服务。图标缓存在本机并跨启动复用 7 天；不可用或断网时显示地球图标，失败请求至少间隔 5 分钟再重试。下载需要沙盒出站网络权限。

## 测试与有界验证

在仓库根目录执行：

```sh
bash scripts/test-core.sh
bash scripts/test-website-icons.sh
```

核心测试覆盖区间边界、域名匹配、合计用时去重、提醒阈值、跨日和数据库重开等行为。网站图标检查覆盖图标获取、HTML 图标发现、缓存和失败兜底。测试命令不代表所有桌面交互与系统权限都已验证。

`--verify-monitoring --verification-seconds 25` 提供有界采集检查：使用独立数据库，不发送自动通知，结束时输出报告并退出。先关闭已有 Timeglow 进程，以免单实例保护将请求交给现有进程。

`--verify-monitoring --verification-performance` 在隔离库执行约 165 秒的统计页、关闭窗口、暂停、恢复序列，输出各阶段时间与暂停前后区间总量。该模式单独关闭闲置排除，避免操作者输入影响性能对比，不修改 Development 或正式库设置。

本地 `verification/` 为开发验证记录，按仓库的 `.gitignore` 不纳入版本控制。
